# 故障排查

修复步骤按破坏性从小到大排列——从最上面开始。下面每一节都以症状命名：找到对应的一节，按顺序往下试，问题消失就停。

## Bot 不回复

1. 打开 Bot 的详情页，看内置的健康检查（**Overview** 标签页）。它覆盖渠道、MCP 和模型配置，会直接指出坏掉的环节。
2. 确认 **通用** 标签页里选了对话模型。没有模型就不可能生成回复——见 [Bot](./bot.md)。
3. 在渠道里发 `/help`。它列出可用命令，并且不经过模型：列表能回来，说明渠道链路是通的，问题在模型侧。见 [斜杠命令](./slash-commands.md)。
4. 检查模型服务商本身：API Key 过期或额度用尽会让所有回复都失败。BYOK 的用量由服务商计费——见 [快速开始](./quick-start.md#使用自己的模型-byok)。

## 渠道接通了但消息没反应

1. 确认该渠道在 **平台** 标签页里处于启用状态。
2. 检查平台凭据是否还是配置时那一份；拿不准就重新保存一次配置。
3. 群聊里要 @ 它——群里的命令写成 `@BotName /help` 这种形式。群聊默认走讨论（discuss）会话，Bot 判断没什么可说时保持沉默也是正常行为——见 [会话](./sessions.md)。
4. 只有部分人得不到回复时，查 [访问控制](./access.md) 的 **渠道成员**：白名单模式下默认拒绝，不在名单里的身份无法触发 Bot。

## 定时任务没有触发

1. 检查 **定时任务** 标签页里的 **Enabled**——停用的任务永远不会跑。
2. 检查 **Max Calls**：达到上限后任务会自动停用。调高或清空上限，再重新启用。
3. 重读 cron 表达式——它按 Bot 的时区计算，`0 9 * * *` 在 Bot 的 9:00 触发，不一定是你的 9:00。见 [定时任务](./schedule.md)。
4. 看同一标签页的运行日志：触发了但执行失败的任务会记录在这里，每次运行也会在会话列表留下一条 schedule 会话——见 [会话](./sessions.md)。

## 工作区命令被拒绝

1. 在 [访问控制](./access.md) 里查当前身份的权限级别：工作区权限按级授予——聊天、读文件、写文件、执行命令、管理——执行命令需要「执行」这一级。
2. 找找有没有等待处理的审批请求：写入和执行类工具调用可能需要人工批准，调用会一直等到有人回应。
3. 检查 Bot 的 **Tool Approval** 设置，它按 Bot 决定哪些工具在运行前需要确认。

## Bot 忘了之前说过的话

1. 长期记忆要在选定记忆提供方之后才生效。看 **记忆** 标签页的状态指示，以及 **通用** 标签页的 **Memory Provider** 字段——见 [长期记忆](./memory.md)。
2. 如果刚发过 `/new`，Bot 已经在新会话里：旧会话内容不会自己带过来，只有写进记忆的部分能跨会话——见 [会话](./sessions.md)。
3. 会话很长时，更早的轮次可能已经被压成摘要。发 `/compact` 主动压缩一次，或检查 Bot 的压缩设置——见 [会话上下文压缩](./compaction.md)。

::: tip 记忆和会话上下文是两回事
记忆是长期的，Bot 的所有会话共用；会话上下文只属于当前这一路对话。想让某件事永久生效，用 [长期记忆](./memory.md)；想给当前对话腾地方，用 [会话上下文压缩](./compaction.md)。
:::

## 回复被截断或很慢

1. 长回复被拆开是有意为之：渠道限制单条消息长度，长输出会拆成连续几条送达。看起来被截断的回复往往只是第一条——等后面几条到齐。
2. 打开会话状态面板看 **Context Usage**。接近模型上下文窗口的会话该压缩了：发 `/compact`，或用 `/new` 重开一路。见 [会话](./sessions.md) 与 [会话上下文压缩](./compaction.md)。

## 联系支持之前

上面的步骤都没解决的话，先收集：

- 你发的原始消息，以及发在哪里——哪个平台、群聊还是私聊、还是应用内；
- Bot 详情页的健康检查结果；
- 定时任务的问题，再带上 **定时任务** 标签页的运行日志。

带上这些去 [帮助中心](https://memoh.ai/help)：账号和订阅类的常见问题在那里有现成答案，也可以从那里联系 Memoh 团队。
